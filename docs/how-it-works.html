Every skill in this repo is a job description. Claude reads one, becomes that specialist, does the work, writes a file, and hands the file to the next specialist. Nothing runs as code — the whole system is a set of instructions plus a filing convention. This page walks the pipeline step by step, then marks what is missing before you build v2.

The mental model

Three ideas hold it together

If someone only takes away three things about how this repo works, make it these.

1 — A skill is an instruction file, not a program

Each SKILL.md has a frontmatter description and a body. The description is the only part Claude reads up front; it is how the model decides whether to use the skill at all. The body loads only once the skill fires. Files in references/ load later still, on demand.

2 — context/ is shared memory, outputs/ is the deliverable

Skills never talk to each other directly. They read and write files in the client folder, and the folder is the state of the engagement. Open Claude Code in a different client folder and you get a different team with a different brand in its head. It also means a session that dies mid-month loses nothing.

3 — Typed fields are the handoff contract

This is the sharpest idea in the repo and the easiest to miss. A skill doesn't just write prose for a human — it writes named fields that a specific downstream skill is instructed to look for. That is what turns ten separate skills into one pipeline.

Step by step

What each skill actually does

Run in order for a new client. In practice most sessions are a single step — the orchestrator's Route E, "just do this one thing".

/social-media-manager

Then routes: A new client, B monthly production, C end-of-month review, D resume mid-workflow, E one-off task, F platform-specific content. It never does the work itself; it invokes a specialist and comes back.

/brand-onboarding
Brand strategist · once per client

Drives a browser to the client's website and Instagram, screenshots both, and extracts everything provable — bio, product range, stated values, customer language, dominant colours, typography feel. Anything read off a screenshot is marked (estimated). Then it generates a client-facing doc that pre-fills the known facts and only asks the genuine gaps: hex codes, fonts, ICP, hero SKUs, do/don't rules. The answers are synthesised into the brand guide every other skill reads.

What's missing

Seventeen gaps, in the order I'd fix them. Tier 1 is the one that matters most: the system plans for content formats it has no way to produce. Everything in pink is not built.

First, what's worth keeping

The typed-field handoff, the hard-stop in /publisher Phase 0, the three data-quality tiers in the review skill, and the "never AI-approximate a real product" rule are all genuinely good design. Carry all four into v2 unchanged — they're the parts that make this feel like an operating system rather than a prompt collection.

Tier 1 — Formats the system plans but cannot make

4 gaps · fix first

Carousels

Not built

The single biggest hole, and you already spotted it. The calendar allocates 25–30% of every month to carousels and calls them the highest-save format. The benchmarks file tracks carousel saves. The review skill is scripted to recommend "increase carousel posts from 2 to 4 per month". And nothing in the repo can produce one — /social-creative-designer mentions "carousel panel" once, as an aspect-ratio option, with no multi-panel logic behind it.

Evidence: content-calendar/SKILL.md:151, :245 · references/content-mix-guide.md:101 · social-performance-review/SKILL.md:225 · social-creative-designer/SKILL.md:57

A dedicated /carousel-designer — spec below.

Reels and short video

Partial

The calendar allocates 20–25% to reels. The only thing that exists is Stop-Motion mode: a six-frame product pour, looped. That's one narrow creative, not a video capability. Nothing writes a hook, a script, a shot list, on-screen text, or a b-roll brief — and nothing handles the far more common case where the client films on a phone and needs the words, not the footage.

Evidence: content-calendar/SKILL.md:152 · social-creative-designer/SKILL.md:198

Split it: /reel-scripter for hook + script + on-screen text + shot list, keep stop-motion as a mode of the designer.

TikTok has no specialist

Asymmetric

TikTok is listed as a supported platform in three skills' frontmatter, and /caption-writer carries TikTok formatting rules. But LinkedIn, Threads and X each got a dedicated writer on the grounds that adapted captions underperform — and that argument applies to TikTok at least as strongly.

Evidence: caption-writer/SKILL.md:177 · content-calendar/SKILL.md:73

Either add /tiktok-writer or drop TikTok from the descriptions. The current half-state routes work to the wrong skill.

Stories

Not built

Brand onboarding asks the client for their Stories share of the format mix; the calendar then explicitly excludes Stories as "supplementary, not in the main calendar". So the data is collected and never used, and the highest-frequency format most SMBs actually post is unsupported.

Evidence: brand-onboarding/SKILL.md:117 · content-calendar/SKILL.md:153

A lightweight weekly Stories sequence generator, or an honest line in the README saying Stories are out of scope.

Proposed skill

/carousel-designer

The hard part of a carousel isn't generating images — it's that eight panels must look like one designed object. Image models drift between calls. You have already solved this exact problem once, in Stop-Motion mode's scene-anchor protocol: define the frame in panel 1 and copy it verbatim into every later prompt. Reuse that discipline for layout instead of scene.

  1. Read the slot. Pull the topic, angle and Visual Direction straight from the calendar entry — the carousel brief already exists there.
  2. Plan the panel arc before generating anything. Hook → promise → 3–7 body beats → proof → CTA. Confirm the arc with the operator, exactly as Stop-Motion confirms its six-frame arc.
  3. Lock a design system. One paragraph — grid, margin, type scale, palette, panel-number position — pasted verbatim into every panel prompt. This is the whole trick.
  4. Enforce safe zones. 1080×1350 (4:5), and keep type clear of the crop Instagram applies in-feed and of the swipe indicator.
  5. Text is the failure mode. Nano Banana garbles small text — the designer skill already warns about this for labels. Offer a text-free panel set the operator can typeset in Canva, and treat that as a first-class output, not a fallback.
  6. Hand off both ways. Write panels to outputs/carousels/ and a matching caption stub back to /caption-writer, so the caption's first line and panel 1's hook are the same promise.

Tier 2 — Jobs a social team does that this doesn't

4 gaps

Engagement and community management

Absent

Roughly half of what an agency bills for social is replying — comments, DMs, inbound enquiries, review responses. There is no skill for any of it. The repo calls itself a complete social media team; right now it's a complete content production team.

A /community-manager that reads brand voice and drafts replies in tiers: routine, needs-a-human, escalate.

Nothing repurposes

Structural

Every platform writer starts from the same calendar entry and writes independently. That's correct for voice, but it means one strong idea is re-derived five times instead of cascading — long-form asset → carousel → reel script → LinkedIn post → three Threads takes. Cascade is where the leverage in this category actually is.

A /repurpose step that takes one source asset and fans it out, with each platform writer as the final pass rather than the first.

No brand-safety or claims gate

Risk

Nothing checks health, food, cosmetic or financial claims, and nothing handles paid-partnership disclosure. For SMB clients in regulated categories — and food brands are used as the running example throughout the repo — a generated caption asserting a health benefit is a real liability.

A pre-publish check inside /publisher, plus a claims section in brand-style.md.

The analytics loop is manual for no reason

Free win

The review skill walks the client through exporting a CSV from Meta Business Suite by hand. Meanwhile Blotato — already a dependency for publishing — exposes post analytics and top-post listing. If a month was scheduled through /publisher, its numbers can be read back automatically.

Have the review skill try Blotato analytics first and fall back to CSV. Keep the manual path for clients who never used the publisher.

Tier 3 — Packaging and mechanics

9 gaps · these are what bite in month two

Install has no update path

Fix in v2

install.sh copies ten folders into ~/.claude/skills/. There's no update command, no uninstall, no version check, and the skill list is hardcoded twice — once in the shell script and once in the batch file. Add a skill in v2 and you will forget one of them. A user who installed last month has no way to know they're stale.

Ship it as a Claude Code plugin with a .claude-plugin/marketplace.json. Users install once and git pull updates everything, and project-scoped installs start working.

Seven of ten skills load everything, every time

Context cost

3,330 lines of instruction, and only caption-writer, content-calendar and social-performance-review use references/. /social-creative-designer is 420 lines, and a Brand-mode session — a single text overlay on a real photo — still loads all four modes' prompt templates.

Keep procedure and routing in SKILL.md; move prompt templates, platform formatting tables and framework libraries into references/. Target under 150 lines per skill.

No scripts/ directory

Determinism

The frames-to-MP4 export is a Python block pasted inside a markdown file for the model to retype each run. Deterministic work belongs in a file that gets executed, not regenerated — retyped code is a new chance to get it wrong every session.

scripts/frames_to_mp4.py with arguments, invoked by the skill. Same for any future export or resize step.

MCP tool names won't resolve as written

Breaks silently

Every Blotato call is namespaced mcp__claude_ai_Blotato__* — a claude.ai connector prefix. A user who adds Blotato as a local MCP server, which is what SETUP.md tells them to do, gets a different prefix and every call misses. Separately, mcp__nanobanana__generate_image is asserted throughout with no server that ships it, and SETUP.md points readers at "the link shared alongside this repo".

Evidence: publisher/SKILL.md — 14 hardcoded tool names · SETUP.md, MCP 2

Ship a .mcp.json, name the real Nano Banana server, and have Phase 0 probe for the capability rather than assume one prefix.

A skill description contradicts the orchestrator

Mis-routes

/caption-writer's frontmatter advertises "Instagram, LinkedIn, Facebook, TikTok, and X". The orchestrator says, twice and in bold, never to use it for LinkedIn or X. The description is the part the model routes on, so the description wins — and the wrong skill fires.

Evidence: caption-writer/SKILL.md:4 vs social-media-manager/SKILL.md — Notes for Operators

Narrow the description to Instagram and Facebook. Audit all ten descriptions for overlap — they are the routing table.

No worked example anyone can look at

Adoption

There is no filled-in brand-style.md, no sample calendar, no example caption set, no creative in the repo — and .gitignore excludes context/, outputs/ and assets/, so nothing demonstrable can ship. A reader has to install the whole thing and onboard a client before seeing a single output.

An examples/demo-client/ with a real brand guide, a real month, five captions and one creative brief. For a public repo this converts better than any amount of README.

No LICENSE file

Housekeeping

The README has a License heading and the words "use it, adapt it, build on it" — with no licence file, that's legally ambiguous for anyone doing client work with it. The same line is also missing its punctuation: "Created by the AI Impact use it".

Add MIT. Fix the sentence. Add a CLAUDE.md so contributors get the house conventions.

No way to tell if a change made output worse

Regression risk

Editing a 400-line skill is editing a prompt. There is no test, no fixture, no eval — so an improvement to one phase can quietly degrade another, and nobody finds out until a client sees it.

A small eval suite per skill, even five fixtures each. skill-creator supports this directly.

The resume file has four writers and no schema

Drift

workflow-status.md is the only durable state and the first thing read on every session. Four skills append to it in prose, and the orchestrator already contains repair logic for files missing the newer fields — which is the tell that the format is drifting.

Define the schema once, in one place, and have every skill write through it.

v2

Where the new skills slot in

The three-layer shape holds. Tier 1 and 2 add five skills, and one of them — repurpose — changes the direction content flows for the first time.

If you only do three things

  • Build /carousel-designer. It's the format the system already promises, already measures, and already recommends more of.
  • Repackage as a plugin. Everything else in v2 gets easier once there's an update path, and everyone still on v1 gets the new skills automatically.
  • Ship a demo client folder. The fastest way to make a stranger understand what this repo does is to let them read one month of its output.
